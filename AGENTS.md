# AGENTS.md — «Гигиена беременности»

## Назначение репозитория

Этот репозиторий является рабочей базой проекта русскоязычной книги
«Гигиена беременности» и единственным постоянным SOURCE OF TRUTH проекта.

При работе с материалами проекта не восстанавливать правила, канон,
медицинские решения или состояние темы по памяти. Использовать актуальные
файлы репозитория.

Файл, который пользователь прямо загрузил в текущий чат как новый материал,
может быть текущим входом в работу. Если он расходится с репозиторием,
сначала определить его статус и не заменять утверждённый канон молча.

## Текущий режим проекта

Проект находится в фазе переработки правил.

- Новые темы не начинаются. Команды `START THEME N` / `CONTINUE THEME N` не запускать без явного нового решения пользователя.
- Темы 1–4 нормативного статуса не имеют. **Темы 1–4 прошли совместную редактуру, содержат незакрытые пометки `[ПРОВЕРИТЬ]` и ожидают ответов врача-консультанта.** Статус STYLE CANON темам не присваивается; эталоном глубины они не являются.
- Действующая спецификация текста и голоса: `editorial/text-architecture-v1.1.md` и `editorial/tone-of-voice-v1.1.md`. Версии `v1.0` обеих — исторические. Опора для новой работы берётся из этих спецификаций; темы 1–3 служат **иллюстрацией применения** этих правил, а не источником правил.
- Следующий шаг проекта — пилотная тема, написанная по новой спецификации.

## Приоритет правил

При конфликте использовать следующий порядок:

1. явное актуальное решение пользователя;
2. медицинская безопасность и проверенные данные;
3. approved canon конкретной темы;
4. активная Content Map — для архитектуры и границ темы;
5. активная Editorial process spec — для порядка процесса;
6. специализированные независимые проверки — каждая в своей функции;
7. исходные тексты и черновики.

Не считать исходный текст, Content Map, ранее написанный текст или модельную
память медицинским доказательством.

## GitHub-first и состояние темы

Постоянное состояние темы восстанавливать прежде всего из GitHub, а не из
предыдущего чата.

Для фактически начатой темы использовать `themes/theme-N/`. Пустые папки
будущих тем заранее не создавать.

`themes/theme-N/README.md` использовать как компактный state record:
текущий и последний утверждённый Checkpoint, актуальный файл, approved
решения, open issues/holds и следующий допустимый шаг. Не дублировать в нём
полный текст главы.

## Стандартные команды

Короткие команды определены в `editorial/project-instructions-v1.8.md`.
Они не создают новых пользовательских gate'ов.

- `START THEME N` — инициализировать фактическую работу над темой и пройти
  входной участок до Checkpoint 0 без лишних промежуточных подтверждений.
- `CONTINUE THEME N` — восстановить состояние из GitHub и продолжить до
  следующего реального пользовательского gate или предусмотренного hold.
- `STATUS THEME N` — read-only статус темы без продвижения workflow.
- `SAVE THEME N` — зафиксировать уже принятое состояние темы в GitHub.
- `SYNC PROJECT` — read-only проверка репозитория: версии, ссылки,
  дубликаты, потерянные пути и валидность навыков в `.claude/skills/`.

Ясная русская формулировка с тем же смыслом может трактоваться как
соответствующая команда.

Сохранять согласованные автоматические связки активной process spec (v1.7):

`Checkpoint 2 → Checkpoint 3`

и после обязательного разрешения перед финальной редактурой:

`Final Russian Book Edit → Depth review №2 / COMPRESSION REGRESSION`.

Prepress-аудит запускается после читательской проверки, а не автоматически за Depth review №2. Regression / Canon Check в v1.7 не отдельный этап, а первый проход prepress-аудита.

Не запрашивать повторное подтверждение gate, если сообщение пользователя уже
явно одобряет текущий gate и просит продолжить.

## Работа с темами

Папки отдельных тем создавать только по мере фактической разработки
или корректировки соответствующей темы.

Не создавать заранее пустые `theme-2/`, `theme-3/` и другие папки.

Для каждой темы сохранять различие между:

- исходным материалом;
- research/evidence;
- рабочим текстом;
- approved content;
- canonical/final text.

Не повышать статус черновика автоматически.

## Уровни проработки

Для оценки существенной информации использовать:

`MENTIONED → PRESENT → EXPLAINED → ACTIONABLE → COMPLETE`

Наличие факта не означает, что он объяснён.
Наличие объяснения не означает, что материал практически применим.

Не сокращать необходимое медицинское объяснение ради ритма,
краткости или «лёгкости текста».

## Медицинские правила

Не придумывать и не исправлять по общему знанию:

- медицинские факты;
- дозы;
- пороговые значения;
- противопоказания;
- диагнозы;
- степень доказательности;
- универсальные назначения;
- источники.

Не усиливать модальность утверждения:
`может` не превращать в `вызывает`,
`обычно` — в `всегда`.

При недостатке доказательств или конфликте данных фиксировать вопрос
для медицинской проверки, а не закрывать его предположением.

## Управление workflow

Единственный executable orchestrator:

`.claude/skills/pregnancy-book-editorial/SKILL.md`

Он обязан следовать активной process spec в `editorial/`.

Специализированные проверки:

- `pregnancy-book-depth-review` — независимая проверка глубины: Depth review №2 / COMPRESSION REGRESSION и по запросу проверка плотности (Depth review №1 как отдельный этап в v1.7 упразднён, его функции в Checkpoint 4);
- `.claude/skills/methodical-review/SKILL.md` — независимая методическая экспертиза; в маршруте книги «Гигиена беременности» этот этап заменён живой экспертизой применимости акушерки-редактора (v1.7, раздел 8), навык остаётся доступен для разовых проверок по прямому запросу;
- `russian-book-editor` — финальная русская книжная редактура после
  Checkpoint 5 и обязательного разрешения пользователя; для этой книги он обязан применять `editorial/tone-of-voice-v1.1.md`, `editorial/text-architecture-v1.1.md` и свой `canonical-style-guide-v1.0.md` (руководство по русскому языку);
- `pregnancy-book-prepress-audit` — финальный независимый prepress-аудит.

Не объединять их роли и не позволять одному инструменту молча заменять другой.

Соблюдать только предусмотренные workflow пользовательские остановки.
Автоматический переход между этапами не даёт права принимать за пользователя
медицинские, архитектурные или авторские решения.

## Навыки

Навыки проекта живут в `.claude/skills/` в этом репозитории и являются
единственным источником. Отдельной установленной копии не существует: в
Claude Code навыки подхватываются автоматически, в веб-интерфейсе claude.ai
читаются как документы через GitHub-коннектор. Действующая версия навыка —
та, что лежит в репозитории; правило `SKILL UPDATE REQUIRED` не применяется.

Подробности — раздел 4 `editorial/project-instructions-v1.8.md`.

Ничего не удалять автоматически.

## Изменения после финальной редакции

После Final Russian Book Edit любая содержательная или текстовая правка
должна пройти предусмотренный активной process spec повторный контроль.

Чисто техническая правка файла или вёрстки, которая не меняет слова,
числа, порядок, смысл или функцию информации, не считается содержательной
редактурой.

## Работа с файлами и версиями

Семантические версии (`v1.8`, `v1.6`, `v3.0` и т. п.) значимы.

Не выбирать историческую версию только потому, что её имя похоже на запрос.

Суффиксы `(1)`, `(2)` и подобные считать техническими только после проверки,
что они не обозначают отдельную содержательную версию.

Не создавать дополнительные копии файлов без необходимости.
История изменений должна сохраняться средствами Git.

## Изменение управляющих документов

Не изменять одновременно:

- архитектуру книги;
- editorial workflow;
- правила специализированных проверок;
- канон;

если задача требует изменения только одного из этих уровней.

При изменении управляющего документа проверить связанные ссылки и роли,
но не переписывать остальные документы без необходимости.

Новая версия управляющего документа становится активной только после
явного принятия пользователем и соответствующего обновления ссылок проекта.
