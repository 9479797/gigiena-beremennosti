# Правила сверки с источниками v1.0

## Назначение

Документ определяет, **как утверждение в тексте связывается с источником** и что происходит, когда источника нет.

Применяется с Checkpoint 2 и далее везде, где в текст попадает медицинское содержание.

---

# 1. НАПРАВЛЕНИЕ РАБОТЫ — ГЛАВНОЕ ПРАВИЛО

> **Источник → утверждение. Никогда не наоборот.**

## Как ломается

Задача «проверь, верно ли, что пить надо каждые 15–20 минут» не работает **никогда**. Подтверждение находится всегда: где-то есть рекомендации по гидратации при нагрузке, где-то похожие цифры для жары, где-то для спортсменов. Агент видит совпадение, ставит `VERIFIED`, прикладывает ссылку. Формально работа сделана. Фактически в книгу для беременных вошёл норматив из спортивной медицины.

Ошибки не было ни на одном шаге. Агент искал подтверждение — и нашёл подтверждение.

## Как работает

Задача: «Открой `sources/russian-guidelines/normalnaya-beremennost.pdf`. Найди всё, что сказано о питьевом режиме. Процитируй дословно с номерами пунктов. Если ничего нет — так и напиши».

Вероятный ответ: конкретного норматива там нет. Значит, фразы про 15–20 минут в книге не появляется. Она не проходит проверку — она **не рождается**.

## Следствие для порядка работы

Утверждения не пишутся, а потом проверяются. Утверждения **выводятся из процитированного фрагмента**. Черновик Checkpoint 1 может содержать пробелы с пометкой «здесь будет то, что найдётся в источнике» — это правильное состояние черновика, а не недоработка.

---

# 2. ПОРЯДОК СВЕРКИ

1. Открыть **конкретный файл** из `sources/`. Не искать в интернете.
2. Найти раздел по оглавлению из `sources/README-inventory.md`.
3. **Процитировать дословно** с номером пункта или раздела. Пересказ не принимается: пересказ — это уже интерпретация.
4. Сформулировать утверждение для книги из процитированного, не добавляя ничего.
5. Записать строку в `themes/theme-N/evidence-ledger.md`.

Ответ **«в источнике этого нет» — нормальный результат**, а не неудача сверки.

Собственные знания агента доказательством не считаются, даже если он полностью уверен. Уверенность модели одинакова и в том, что она знает, и в том, что придумала, — это и есть причина, по которой правило существует.

---

# 3. ИЕРАРХИЯ ИСТОЧНИКОВ ПО ФУНКЦИИ

Не по авторитету источника, а по тому, **что именно из него берётся**.

| Что берём | Откуда допустимо |
|---|---|
| Пороги, дозы, сроки, критерии обращения к врачу, противопоказания | **Только** `russian-guidelines/`. При их молчании — `who-international/` с явной отметкой о применимости к РФ |
| Границы нормы, «когда это уже не норма» | Рекомендации по **соответствующей патологии**, не по нормальной беременности |
| Цифры эффекта вида «снижает риск на N%» | **Только** систематические обзоры и метаанализы. Никогда из одного исследования |
| Механизмы, физиология, объяснение «почему» | `russian-guidelines/` (разделы об этиологии и жалобах), `physiology/`, обзоры, периодика |
| Терминология, контекст российской практики | `russian-guidelines/`, периодика |
| Карта читательских вопросов | `patient-materials/`, форумы. **Утверждения не переносятся** |

Международное руководство не переносится в российский контекст без проверки применимости. При расхождении между российскими и международными рекомендациями — `UNRESOLVED` и вопрос рецензенту, а не выбор в свою пользу.

---

# 4. PUBMED КАК ИНСТРУМЕНТ

PubMed — не папка в `sources/`, а инструмент точечного поиска. Скачать каталог из десятков миллионов статей нельзя; он обслуживает конкретные пробелы.

## Когда используется

Только по заявке из разведки темы с пометкой `МЕХАНИЗМ НЕ НАЙДЕН`. Не для проверки уже написанного утверждения — это нарушение правила о направлении работы.

## Порядок

1. Искать **обзор или метаанализ**, а не отдельное исследование.
2. Приоритет — PubMed Central, где доступен полный текст.
3. **Реферат источником не считается.** Рефераты систематически преувеличивают результат; цитирование по реферату — известная ошибка. Если полного текста нет, утверждение получает `SOURCE NEEDED`.
4. Записать в ledger: название, авторы, год, PMID, тип публикации, что именно взято.

## Ограничение

Из первичной литературы **не берутся пороги, дозы и критерии обращения к врачу**, даже если в статье они названы. Эти величины приходят только из клинических рекомендаций.

Причина: оценить применимость конкретного исследования к российской читательнице — работа клинического эпидемиолога, и в проекте её делать некому. Рецензент подключается один раз и читает текст, а не литературу.

Всё, взятое из первичной литературы, идёт рецензенту **отдельной строкой** с пометкой, что это статья, а не норматив.

---

# 5. РОССИЙСКАЯ ПЕРИОДИКА

Правила использования — в `sources/periodicals/README.md`. Ключевое здесь:

**Обязательная проверка коммерческого интереса.** Если в статье упомянут конкретный препарат по торговому наименованию или указана поддержка производителя — статья не используется для этого утверждения вообще, даже как источник механизма.

Периодика не перевешивает клинические рекомендации. При расхождении — `UNRESOLVED`.

---

# 6. СТАТУСЫ

| Статус | Значение |
|---|---|
| `VERIFIED` | Процитировано из источника нужного уровня, применимость проверена |
| `QUALIFIED` | Подтверждено с оговоркой: ограниченная популяция, спорная применимость, устаревающий документ |
| `CORRECTED` | Исходная формулировка была неверна, исправлена по источнику |
| `EXPANDED` | Утверждение было неполным, дополнено из источника |
| `UNRESOLVED` | Источники противоречат друг другу либо вопрос открыт |
| `SOURCE NEEDED` | Цитаты нет; требует решения пользователя и проверки рецензентом |
| `REVIEWER VERIFIED` | Подтверждено медицинским рецензентом |
| `REVIEWER CORRECTED` | Исправлено по замечанию рецензента |
| `REVIEWER REJECTED` | Отклонено рецензентом, снято из текста |

---

# 7. УТВЕРЖДЕНИЯ БЕЗ ИСТОЧНИКА

## 7.1. Не удаляются автоматически

Утверждение без цитаты получает `SOURCE NEEDED` и остаётся в тексте до решения пользователя. Автоудаление теряет верное содержание: общеизвестной физиологии в клинических рекомендациях может не быть просто потому, что они пишутся не для этого.

## 7.2. Конкретность не размывается

Читателю нужны ориентиры. Расплывчатая формулировка не просто хуже читается — **она не выполняет функцию**: по ней нельзя действовать. Спорный ориентир помечается и проверяется, а не заменяется общими словами.

## 7.3. Список для решения

В конце Checkpoint 5 выводится полный список `SOURCE NEEDED`, разделённый на две части. **Разделение обязательно.**

### Часть 1 — требует подтверждения

Известные положения, под которые источник не открывался или в источнике не нашлось.

Вопрос рецензенту: **«подтверждаете?»**

### Часть 2 — сформулировано автором

Утверждения, выведенные моделью самостоятельно: сравнения силы, дозовые режимы, частотные оценки, причинно-следственные связи, не названные в источниках.

Вопрос рецензенту принципиально другой: **«существует ли такая рекомендация вообще, или это придумано?»**

Разделение нужно потому, что в первом случае врач вспоминает, а во втором — оценивает правдоподобие, то есть делает то же самое, что делала модель, породившая утверждение. Без явной пометки он не заметит разницы между «крови примерно на 40% больше» и «час сидения нагружает вены сильнее часа ходьбы»: оба звучат одинаково убедительно, но первое он знает, а второе только оценивает.

### Обязательные поля каждой строки

- утверждение дословно;
- номер узла;
- **где искали и что нашли** — «раздел о физической активности есть, питьевой режим не описан» и «не искали» суть разные вещи; без этого поля пользователь решает вслепую;
- приоритет: красные флаги и пороги — первыми.

## 7.4. Исходы

По каждой строке один из трёх:

1. оставить для проверки рецензентом;
2. переформулировать так, чтобы утверждение опиралось только на подтверждённое;
3. снять.

Утверждение, отклонённое рецензентом, снимается; узел перестраивается без него, **сохраняя механизм и конкретное действие**.

# 8. ФОРМАТ ПОМЕТКИ `[ПРОВЕРИТЬ]`

## 8.1. Единственная пометка проекта

В тексте темы используется одна пометка — `[ПРОВЕРИТЬ]`. Пометки `[ВОПРОС ЮЛИИ]`, `[ИСТОЧНИК]`, `[ОТ РЕДАКТОРА]`, `[ОСПОРЕНО]` к использованию не назначаются. Существующие вхождения приводятся к `[ПРОВЕРИТЬ]` **с сохранением текста внутри** — заменяется имя пометки, не содержание.

`SOURCE NEEDED` остаётся **статусом в evidence ledger** (раздел 6, раздел 7.3); `[ПРОВЕРИТЬ]` — его отметка в самом тексте.

## 8.2. Пометка ставится после проверки

`[ПРОВЕРИТЬ]` ставится не вместо проверки, а после неё. Внутри пометки указывается: **что именно проверено** и **почему вопрос остался открытым**. «Проверить, так ли это» без указания, что уже сделано, — не пометка, а перекладывание работы.

## 8.3. «Не нашёл» и «стандарта не существует» — разные записи

- **Не нашёл.** Источник может существовать, доступ не получен. Пометка временная, автор закрывает её после ответа консультанта.
- **Стандарта не существует.** Проверка показала, что протокола/порога по этому вопросу нет ни в российских рекомендациях, ни в доступной литературе. Пометка фиксирует **отсутствие протокола прямо**, чтобы вопрос не искали повторно в следующей сессии.

## 8.4. Вопрос консультанту — с готовым вариантом текста

Вопрос врачу-консультанту формулируется не как «что здесь верно?», а с **готовым вариантом формулировки**, который консультант может одобрить или отклонить. Это переносит работу по формулировке на автора, а на консультанта — только решение.

## 8.5. Отношение к другим пометкам

- **`[ОЧЕВИДНОЕ?]`** (`editorial/tone-of-voice-v1.1.md`, раздел 9) — авторская пометка к самому себе о том, что абзац, возможно, объясняет очевидное. Это не пометка сверки: её ставит и закрывает автор, консультанту она не адресуется.
- **Оспоренное утверждение** (`editorial/text-architecture-v1.1.md`, раздел 9) — частный случай `[ПРОВЕРИТЬ]`: утверждение конфликтует с уже установленным в проекте фактом. Отличия: пометка не снимается автором единолично и не убирается из чистой читательской версии; разрешение — отдельный общий этап после черновиков всех тем.

## 8.6. Единый реестр открытых вопросов

Открытые вопросы к врачу-консультанту (оспоренные утверждения и вопросы «оставить/снять», «применимо ли в РФ», «какой из расходящихся порогов») ведутся в `editorial/DISPUTED-CLAIMS.md` — **едином реестре по всем темам**. `evidence-ledger.md` темы и раздел OPEN ISSUES в её README ссылаются на реестр, а не повторяют его содержание. Рабочие `SOURCE NEEDED` / `UNRESOLVED` строки ledger в реестр не переносятся — это отдельная категория, её закрывает автор поиском источника.

# 9. ЧТО ЗАПРЕЩЕНО АГЕНТУ СВЕРКИ

1. Искать подтверждение уже написанному утверждению.
2. Принимать пересказ вместо дословной цитаты.
3. Считать доказательством собственные знания.
4. Ставить `VERIFIED` по совпадению темы без совпадения условий: цифра из рекомендаций для другой популяции подтверждением не является.
5. Цитировать по реферату, когда доступен полный текст, или выдавать реферат за источник.
6. Использовать статью с коммерческим интересом.
7. Скрывать пустой результат. «Не нашёл» пишется прямо.
8. Переносить утверждения из пациентских материалов и форумов.
9. Молча смягчать или усиливать формулировку источника. Изменение модальности — отдельное редакционное действие, оно фиксируется в ledger.

---

# 10. ГРАНИЦЫ

Сверка не заменяет медицинскую экспертизу. Она устанавливает, **есть ли под утверждением источник**, а не является ли утверждение верным.

Окончательное медицинское суждение выносит рецензент по `editorial/human-review-roles-v1.0.md`.
