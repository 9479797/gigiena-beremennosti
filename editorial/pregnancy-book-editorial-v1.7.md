# Editorial Process Spec v1.7

**PROCESS AUTHORITY / SOURCE OF TRUTH** для порядка этапов, остановок, автоматических переходов, возвратов и финального принятия тем.

Это спецификация процесса, а не исполняемый навык. Единственный executable `$pregnancy-book-editorial` — `.claude/skills/pregnancy-book-editorial/SKILL.md`; он обязан следовать этому файлу.

## Что изменилось относительно v1.6

Версия написана после разбора Темы 3, показавшего, что двенадцать модельных проверок пропустили выдуманные числа, разбавленность и смену жанра.

Вывод: дело было не в нехватке контроля. Модельные проверки дёшевы и слепы к этим дефектам. Поэтому v1.7 **сокращает модельные этапы и добавляет живых участников**.

| | v1.6 | v1.7 |
|---|---|---|
| Модельных этапов | 16 | 11 |
| Живых участников | пользователь | пользователь, акушерка-редактор, врач-рецензент |
| Входной участок | SOURCE AUDIT + COVERAGE + GAP ANALYSIS | разведка темы |
| Checkpoint 2 и 2A | раздельно | объединены |
| Depth review №1 | отдельный этап | поглощён Checkpoint 4 |
| Regression / Canon Check | отдельный этап | первый проход prepress-аудита |
| Methodical review | модельная проверка | живая акушерка-редактор |

Язык документа изменён на русский — по соответствию остальному набору спецификаций.

# 1. МАРШРУТ

```
РАЗВЕДКА ТЕМЫ
  → Checkpoint 0 — Спина темы                          [gate]
  → Checkpoint 1 — Черновик                            [gate]
  → Checkpoint 2 — Медицинская сверка и расширение
  → Checkpoint 3 — Анти-шаблон и человечность          [gate]
  → Checkpoint 4 — Плотность, композиция и подача      [gate]
  → 🔵 ЭКСПЕРТИЗА ПРИМЕНИМОСТИ — акушерка-редактор
  → Встраивание замечаний акушерки
  → Checkpoint 5 — Заморозка содержания                [gate]
  → 🔴 МЕДИЦИНСКАЯ ПРОВЕРКА — врач-рецензент
  → Встраивание медицинских правок
  → ОБЯЗАТЕЛЬНЫЙ USER STOP
  → Final Russian Book Edit
  → Depth review №2 / Compression Regression
  → 👤 ЧИТАТЕЛЬСКАЯ ПРОВЕРКА — пользователь
  → Prepress-аудит
  → READY FOR PRINT / READY AFTER MINOR FIXES / NOT READY FOR PRINT
```

Разметка участников, что им отправляется и что они возвращают — `editorial/human-review-roles-v1.0.md`.

## Пользовательские gate'ы

После Checkpoint 0, 1, 3, 4, после Checkpoint 5 и обязательно перед финальной редактурой.

## Автоматические переходы

- `Checkpoint 2 → Checkpoint 3` — без промежуточного подтверждения;
- после разрешения перед финальной редактурой: `Final Russian Book Edit → Depth review №2`.

Prepress-аудит запускается **после** читательской проверки, а не автоматически за Depth review №2.

Автоматический переход не даёт права угадывать или скрывать проблему.

## Остановки

| Hold | Когда |
|---|---|
| `MEDICAL HOLD` | Безопасное продолжение невозможно без доказательства или медицинского решения |
| `CANON CONFLICT` | Правка противоречит одобренному канону |
| `AUTHOR DECISION REQUIRED` | Есть несколько содержательно разных решений |
| `AMBIGUOUS_MEANING` | Смысл нельзя восстановить однозначно |
| `SOURCE MISSING` | Для темы нет документа, задающего границы нормы |
| `USER DECISION REQUIRED` | Есть нерешённые `SOURCE NEEDED` |
| `MIDWIFE REVIEW PENDING` | Отправлено акушерке, ответа нет |
| `MEDICAL REVIEW PENDING` | Отправлено врачу, ответа нет |

# 2. РАЗВЕДКА ТЕМЫ

Полностью описана в `editorial/theme-reconnaissance-v1.0.md`.

Заменяет входной участок v1.6 (`SOURCE AUDIT → CONTENT COVERAGE → предварительный EVIDENCE & GAP ANALYSIS`): три этапа сворачиваются в один, потому что все три отвечали на один вопрос — что есть по теме.

Результат — список кандидатов в узлы с указанием происхождения. Отчёт уходит пользователю; он отбирает.

**Разведка не порождает медицинских утверждений.**

Если для темы нет документа, задающего границы нормы, объявляется `SOURCE MISSING`. Работа над блоками «когда обращаться к врачу» не начинается.

# 3. CHECKPOINT 0 — СПИНА ТЕМЫ

Заменяет «Reader Job + Architecture».

## Что фиксируется

1. Reader job и состояние читательницы до и после.
2. **Спина темы**: 6–9 узлов по `editorial/text-architecture-v1.0.md`. Для каждого — формулировка, почему неочевиден, уровень проработки (`ГЛУБОКО` / `СРЕДНЕ` / `ОДНА СТРОКА`), какой источник нужен.
3. Границы темы и cross-links.
4. Инициализация `themes/theme-N/evidence-ledger.md` по шаблону.

Финальную прозу не писать.

## Coverage и спина — разные вещи

> Coverage-список Content Map — **перечень обязательного покрытия**, а не оглавление главы.

Спина строится так, чтобы закрыть все пункты coverage, но их количество числа узлов не определяет. Несколько пунктов coverage закрываются одним узлом, если у них общий механизм и общий вывод.

Тема, где каждый пункт coverage стал отдельным разделом, спроектирована неправильно: так получается инвентарь, а не объяснение.

Тема, где все узлы помечены `ГЛУБОКО`, спроектирована неправильно тоже.

**Всё, что не ложится ни на один узел спины, в черновик не пишется.**

`GATE`

---

# 4. CHECKPOINT 1 — ЧЕРНОВИК

Первый книжный черновик по спине. Приоритет: голос, вход в тему, узнавание, движение текста, практическая польза.

## Черновик с пробелами — правильное состояние

Утверждения выводятся из источника, а не пишутся с последующей проверкой (см. раздел 5). Поэтому черновик содержит пометки вида:

> `[ИСТОЧНИК: КР «Нормальная беременность», раздел о жалобах — что там сказано об отёках]`

Такие пробелы — **не недоработка**. Заполнить их догадкой значит создать утверждение, под которое потом будут подбирать подтверждение.

Финальную языковую полировку не делать.

`GATE`

---

# 5. CHECKPOINT 2 — МЕДИЦИНСКАЯ СВЕРКА И РАСШИРЕНИЕ

Объединяет Checkpoint 2 и 2A из v1.6. Разделение было историческим: оба этапа занимались медицинским содержанием.

Правила работы с источниками — `editorial/source-verification-v1.0.md`. Ключевое здесь:

> **Источник → утверждение. Никогда не наоборот.**

## Три задачи

**Сверка.** Открыть конкретный файл из `sources/`, найти раздел, процитировать дословно, сформулировать утверждение из процитированного. Ответ «в источнике этого нет» — нормальный результат.

**Коррекция.** Спорное утверждение не удаляется молча: сохраняется зачёркнутым в redline, записывается, почему сомнительно, что найдено и какая замена предлагается.

**Расширение.** Клинически важные места, слишком мелкие для платной медицинской книги, углубляются — из источника, а не из памяти.

## Проверка глубины узла

Каждый узел проверяется по цепочке `WHAT → WHY → RECOGNITION → ACTION → NEXT STEP → SAFETY` и по лестнице `MENTIONED / PRESENT / EXPLAINED / ACTIONABLE / COMPLETE`.

Наличие факта не есть раскрытие темы.

Если неочевидное следствие узла не подтверждается источником — **узел строится без него**, на механизме, действии и границе. Яркий выдуманный вывод хуже честного скучного узла.

`АВТОМАТИЧЕСКИЙ ПЕРЕХОД → Checkpoint 3`

Остановка только при `MEDICAL HOLD`, `CANON CONFLICT` или `AUTHOR DECISION REQUIRED`.

---

# 6. CHECKPOINT 3 — АНТИ-ШАБЛОН И ЧЕЛОВЕЧНОСТЬ

Убрать шаблонность, декоративные противопоставления, искусственные выводы, общие утешения, механический ритм — не сокращая функцию текста.

Применять `editorial/tone-of-voice-v1.0.md`: три регистра, три режима речи, правило модальности, ввод терминов, присутствие автора.

Голос применяется **здесь**, а не только на финальной редактуре: к моменту финала устройство абзацев и ритм уже застыли, и полировка интонацию не создаёт.

`GATE`

---

# 7. CHECKPOINT 4 — ПЛОТНОСТЬ, КОМПОЗИЦИЯ И ПОДАЧА

Переформулирован. В v1.6 назывался «Lists, Rhythm & Presentation» и занимался оформлением. Теперь это **основной барьер против разбавления** — дефекта, который в v1.6 не проверял никто.

Поглощает Depth review №1.

## Что проверяется

По `editorial/text-architecture-v1.0.md`, раздел 3:

1. **Тест на неочевидность** — для каждого объяснительного абзаца: что читательница узнала, чего не могла угадать? Не применяется к красным флагам и навигации.
2. **Анонсы и итоги** — их не должно быть.
3. **Один завершающий блок** на тему, не четыре.
4. **Одна мысль — один дом**; безопасность повторяется намеренно.
5. **Расплющивание** — механизм, поданный пунктом списка, разворачивается в прозу. Таблица оправдана, только когда читательница сравнивает варианты.
6. **Примеры различают**, а не иллюстрируют сказанное.

## Проверка глубины в обе стороны

Раньше проверялась только потеря глубины. Теперь также: **не длинный ли текст при низкой плотности**. Оба дефекта равнозначны.

Если обнаружен содержательный пробел — возврат в Checkpoint 2.

`GATE`

---

# 8. ЭКСПЕРТИЗА ПРИМЕНИМОСТИ — АКУШЕРКА-РЕДАКТОР 🔵

Заменяет модельный methodical review. Живой специалист с практикой проверяет то же самое плюс реальность.

Отправляется чистый текст без служебных пометок и лист вопросов (`editorial/human-review-roles-v1.0.md`, раздел 3): что не работает в жизни, каких вопросов не хватает, где рекомендация верна, но невыполнима, что женщины обычно понимают неправильно, где читается тяжело.

Числа, дозы и пороги ей не адресуются — это к врачу.

`MIDWIFE REVIEW PENDING` до ответа. Переход к Checkpoint 5 запрещён.

## Встраивание замечаний

Замечания встраиваются автором, а не накладываются заплатками. Если замечание затрагивает структуру узла — возврат в Checkpoint 4.

---

# 9. CHECKPOINT 5 — ЗАМОРОЗКА СОДЕРЖАНИЯ

Зафиксировать содержательно готовую версию: медицинская целостность, полнота, доказательные границы, числа, термины, практические действия, safety-net, соответствие спине.

Проверить, что **все пункты coverage закрыты** хотя бы одной строкой в каком-то узле.

Статус: `CONTENT READY / CONTENT READY WITH FLAGS / CONTENT REQUIRES REVISION`.

## Список SOURCE NEEDED

Выводится здесь, в формате `editorial/source-verification-v1.0.md`, раздел 7.3 — **разделённый на две части**:

- **требует подтверждения** — известные положения без открытого источника;
- **сформулировано автором** — сравнения, дозовые режимы, частотные оценки, выведенные моделью.

Разделение обязательно: в первом случае врач вспоминает, во втором оценивает правдоподобие, то есть делает то же, что делала модель, породившая утверждение.

Пользователь решает по каждой строке: оставить для проверки врачом, переформулировать, снять.

Конкретные ориентиры — числа, интервалы, сроки — **не размываются ради безопасности формулировки**. Читателю нужны якоря. Спорный ориентир помечается и проверяется, а не заменяется общими словами.

`USER DECISION REQUIRED` пока строки не разрешены.

Финальную литературную редактуру здесь не выполнять. Замороженная версия — semantic baseline.

`GATE`

---

# 10. МЕДИЦИНСКАЯ ПРОВЕРКА — ВРАЧ-РЕЦЕНЗЕНТ 🔴

Отправляются три файла: текст, evidence ledger, список `SOURCE NEEDED`.

Врач возвращает по каждому утверждению: `REVIEWER VERIFIED` / `REVIEWER CORRECTED` / `REVIEWER REJECTED` / `UNRESOLVED`.

**Врач не переписывает текст.** Он указывает, что неверно; формулировку делает автор.

`MEDICAL REVIEW PENDING` до ответа. Финальная редактура не запускается.

## Встраивание медицинских правок

Отклонённое утверждение снимается; узел перестраивается без него, **сохраняя механизм и конкретное действие**.

Правки рецензента — авторизованное изменение содержания. Полного повтора маршрута не требуют. Если правка затрагивает структуру узла — возврат в Checkpoint 4.

---

# 11. ОБЯЗАТЕЛЬНЫЙ USER STOP

Финальная редактура начинается только после явного разрешения пользователя.

---

# 12. FINAL RUSSIAN BOOK EDIT

`$russian-book-editor` в режиме `BOOK EDIT`. Semantic baseline — версия Checkpoint 5 с встроенными правками врача.

До правок зафиксировать semantic lock: факты, числа, модальность, термины, практические действия, safety-net, cross-links, approved canon.

Последовательность: `CONTEXT PASS → SEMANTIC LOCK → LOGIC MAP → RUSSIAN RECONSTRUCTION → READER MISINTERPRETATION TEST → SEMANTIC REGRESSION`.

`LANGUAGE_ONLY` и `LOGIC_RECOVERABLE` исправляются самостоятельно. При `AMBIGUOUS_MEANING` — только выборочный redline и остановка. При `CONTENT_OR_MEDICAL_GAP` — возврат в Checkpoint 2.

Редактор не восполняет медицинские пробелы догадкой.

Последний этап разработки, которому разрешено менять текст.

`АВТОМАТИЧЕСКИЙ ПЕРЕХОД → Depth review №2`

---

# 13. DEPTH REVIEW №2 / COMPRESSION REGRESSION

Сравнить отредактированный текст с замороженной версией Checkpoint 5. Проверить, не потеряны ли объяснение, причинная связь, действие, следующий шаг, исключение, функция примера, граница безопасности.

Функция была на Checkpoint 5 и исчезла при редактуре → возврат в `$russian-book-editor`.
Функции не было уже в baseline → возврат в Checkpoint 2.

---

# 14. ЧИТАТЕЛЬСКАЯ ПРОВЕРКА 👤

Пользователь читает готовый текст **подряд, как читатель**, а не как проверяющий. Вопрос один: где стало скучно и где непонятно.

Этап введён потому, что скука не обнаруживается изнутри текста. Все модельные проверки — это модель, читающая собственный вывод. Тема 3 прошла двенадцать таких проверок и получила статус канона.

Замечания по интересности возвращаются в Checkpoint 4, по непонятности — в Checkpoint 2 или в финальную редактуру в зависимости от причины.

---

# 15. PREPRESS-АУДИТ

Поглощает Regression / Canon Check из v1.6 как первый проход: аудит и так читает approved canon, decisions, evidence ledger и Regression Watch.

## Проход 1 — регрессия и канон

Сопоставить итог с approved canon, decisions, evidence ledger, Regression Watch. Проверять не наличие фразы, а сохранение её функции, степени уверенности, условий и границ безопасности.

## Проход 2 — вердикт

`READY FOR PRINT / READY AFTER MINOR FIXES / NOT READY FOR PRINT`.

## Блокирующие условия

Положительный вердикт невозможен, если:

- в ledger остались `SOURCE NEEDED` или `UNRESOLVED` без разрешения;
- не пройдена медицинская проверка;
- не заполнена отметка о внешней проверке в ledger;
- не закрыт хотя бы один пункт coverage.

## Класс дефекта «разбавленность»

Разбавленность — избыточный объём при низкой плотности — **не относится к классу `OPTIONAL`**. Это дефект содержания и учитывается как `MAJOR` или `MINOR` по масштабу.

Пока она числилась в `OPTIONAL`, она по определению не могла заблокировать тему. Так Тема 3 прошла аудит.

# 16. ШЛЮЗ ВНЕШНИХ ПРАВОК

Правила v1.6 описывали изменения внутри процесса, но не описывали текст, изменённый **снаружи**. Через эту дыру в проект пришли обе внешние редакции Темы 3.

> Текст, отредактированный вне маршрута — другой моделью, сторонним редактором, любым инструментом — входит в проект как **предложение**, а не как версия.

Порядок приёма:

1. Зафиксировать, что изменилось, относительно последней версии в репозитории.
2. Проверить на смену регистра и аудитории.
3. Проверить все появившиеся числа, пороги и сравнения — они не проходили сверку.
4. Сверить с approved canon: нет ли противоречий уже утверждённому.
5. Только после этого решать, принимать ли.

Внешняя редакция не заменяет канон молча ни при каких обстоятельствах.

---

# 17. ОСОБЫЕ ЕДИНИЦЫ КНИГИ

Раздел 0, Введение и Orientation section — **другого жанра**. Раздел 0 навигатор: распознать → понять срочность → действовать. Введение — инструкция по пользованию книгой.

Структура узла (`узнавание → механизм → неочевидное следствие`) к ним не применяется. В Разделе 0 неочевидное следствие вредно: нужна мгновенная находимость, а не открытие.

Для них применяются: правила плотности, тон изложения, правила сверки, участники проверки. Не применяются: структура узла, спина из 6–9 узлов, тест на неочевидность.

---

# 18. ПРАВИЛА ВОЗВРАТА

- Медицинский или содержательный пробел → Checkpoint 2, затем повторяются затронутые проверки, Checkpoint 5, STOP и финальная редактура.
- Разбавленность или дефект композиции → Checkpoint 4.
- Потеря принятой функции при финальной редактуре → `$russian-book-editor`, затем Depth review №2 и prepress.
- Любая содержательная правка после финальной редактуры → повторить финальную редактуру и затронутые проверки. Перед новым входом в prepress обязательны свежие Depth review №2 для точной версии текста.
- Чисто техническая правка файла или вёрстки, не меняющая слова, числа, порядок, смысл или функцию, допускает локальный technical minor-fix pass.
- **Локальный дефект не перезапускает тему.** Возвращается только затронутый фрагмент в ответственный этап.

# 19. НЕИЗМЕННЫЕ ПРИНЦИПЫ

- Единица редактирования — понимание читательницы, а не отдельное предложение.
- Не сокращать объяснение ради лёгкости, ритма или инфостиля.
- Сокращать повтор, но не функцию информации.
- Не выдавать список за объяснение, число за рекомендацию, гладкий текст за понятный.
- Не усиливать степень уверенности: `может` не превращать в `вызывает`, `обычно` — в `всегда`.
- Не изобретать медицинские факты, дозы, противопоказания, диагнозы, источники, универсальные назначения.
- Не считать source text, content map, ранее написанный текст или модельную память медицинским доказательством.
- Не смешивать отчёты разных проверок в один неразличимый список.
- Не собирать DOCX до утверждения финального текста или явного запроса пользователя.
- Уверенность модели одинакова в том, что она знает, и в том, что придумала. Все правила сверки следуют отсюда.

# 20. РЕЖИМЫ РАБОТЫ

## ITERATIVE_EDITORIAL

Режим по умолчанию.

## FULL_REWRITE

Только по явной просьбе пользователя. Меняет ритм взаимодействия, но не порядок этапов и не гейты безопасности. Не используется для обхода пользовательских остановок, обязательного STOP, медицинских и канонических holds.

# 21. СОСТОЯНИЕ ТЕМЫ

Поддерживать в `themes/theme-N/`:

- `README.md` — state record: текущий и последний утверждённый этап, актуальный файл, approved decisions, open issues и holds, следующий допустимый шаг;
- `evidence-ledger.md` — журнал утверждений по шаблону;
- `APPROVED CANON`, `DECISIONS`, `REGRESSION WATCH` — в README либо отдельными файлами.

Никогда не перезаписывать approved canon молча.
