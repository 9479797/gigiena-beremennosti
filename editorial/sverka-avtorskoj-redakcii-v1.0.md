# Сверка авторской редакции (REVIEW THEME N)

Этап для темы, которую автор переписал сам и прислал файлом. Задача — не переписать текст, а проверить его и предложить только необходимые правки в редлайне, раздел за разделом, и собрать единый файл для проверки автором. Порядок отработан на Теме 8 (26–27.10.2026).

Основа: `editorial/standart-redaktury-v1.4.md` (разделы 9 и 10), правила `AGENTS.md` от 23 и 27.10.2026, `editorial/html-navigaciya.md` (раскрывающиеся блоки), `editorial/format-spiska-istochnikov-v2.0.md`.

## Команда

`REVIEW THEME N` — автор прислал свою переработку темы N. Ясная русская формулировка с тем же смыслом («держи тему 9, начинай проверку», «проверь тему 10») равнозначна команде.

## Шаг 1. Анализ темы (только чтение, текст не меняется)

1. Прочитать файл целиком. Сравнить с версией в репозитории: объём, состав разделов, что добавлено и что исчезло.
2. Карта и нумерация: только N.N (третьего уровня нет), пропуски номеров, разделы не на своём месте, устаревшие ссылки на номера внутри темы, повторы внутри темы, таблицы без вводной фразы.
3. Пометки для врача прежней версии: перечислить; для каждой позже записать решение — закрыта текстом, нужна снова, снята.
4. Отсылки на другие темы: перечислить, сверить номер и название по `editorial/soderzhanie-knigi.md` и спискам перенумерации (`themes/theme-N/perenumeraciya-*.md`).
5. Сверка с Разделом 0: срочность, маршрут, признаки и действия в теме против строк `themes/theme-0/draft.md`.
6. Числа и пороги против тем, проверенных врачом.
7. Новые факты: список для адресной проверки по разделам; сразу проверить самые рискованные (законы и даты, цифры исследований, маршруты).
8. Отчёт в `themes/theme-N/proverka-ГГГГ-ММ-ДД.md` и короткий отчёт в чате.

## Шаг 2. Уточняющие вопросы

Спрашивать всё, что решает автор и что не решено правилами проекта, — столько вопросов, сколько нужно (решение пользователя 27.10.2026: ограничения по числу нет). Уже решено и не спрашивается:

- подробности сохраняются, компактность — раскрывающиеся блоки;
- торговые марки сохраняются;
- при расхождении главный Раздел 0;
- отсылки на другие темы сверяются и сохраняются, нужный материал — на месте;
- пометки для врача определяются заново;
- источники — после утверждения текста, силами источниковеда;
- нумерация только N.N;
- правка — только необходимое.

Примеры вопросов, которые задавать нужно: перенос или объединение разделов; судьба крупного блока, который выходит за границы темы; противоречие автора самому себе; содержательный выбор, которого нет в Разделе 0.

После ответов решения записываются в `proverka-*.md` и, если это новое общее правило, — в `AGENTS.md`.

## Шаг 3. Правка по разделам — самостоятельно, раздел за разделом

Для каждого раздела, по порядку, без остановки между разделами:

1. Прочитать раздел.
2. Адресно проверить новые факты (PubMed, официальные сайты, тексты законов и клинических рекомендаций). Что не удалось подтвердить — в очередь источниковеду, текст не менять.
3. Править только при причине:
   - ошибка или неточность факта, цифры, ссылки на документ;
   - расхождение с Разделом 0 или темами, проверенными врачом;
   - отсылка вместо нужного материала;
   - неясно, что делать и куда обращаться;
   - повтор внутри темы;
   - нарушение правила проекта (в том числе тон, пункт 9.11 стандарта);
   - связка («Однако», «Таким образом»), которая ссылается на текст, ушедший в свёрнутый блок.
   Стилистика и формулировки автора без такой причины не переписываются.
4. Расхождение с Разделом 0: текст темы пишется заново по строке Раздела 0, прежний — зачёркнут, рядом `[ПРОВЕРИТЬ: расхождение с Разделом 0, строка «…» — в теме было «…»; текст приведён к Разделу 0]`. Верное уточнение темы, которого нет в Разделе 0, тоже уходит в зачёркнутое и в пометку с вопросом врачу, дополнить ли Раздел 0.
5. Отсылки на другие темы: формат «Подробнее — Тема N, раздел N.N «Название»»; нужное — на месте; запись в `themes/theme-N/otsylki.md`.
6. Раскрывающиеся блоки: механизмы, исследования, физика и химия, примеры марок. Перед блоком в основном тексте должен остаться вывод, чтобы тема читалась без раскрытия. Блоки не вкладываются друг в друга.
7. Пометки для врача — только там, где действительно нужен врачебный выбор.
8. Файл раздела: только этот раздел, в начале — причины правок, что проверено без правки, очередь источниковеду. Раздел без правок — без файла, с записью в ведомости.
9. Записать раздел в `proverka-*.md`, коммит, отправить файл пользователю, перейти к следующему разделу.

## Шаг 4. Единый файл для проверки автором

Собрать все разделы в один редлайн всей темы: в начале — условные обозначения; перед каждым разделом курсивом — причины правок и что проверено. Записать в README темы. После решений автора — сборка принятого текста, оглавление (`editorial/soderzhanie-knigi.md` и `.docx`), реестр отсылок, затем `SAVE THEME N`.

## Оформление

- Удалённое — красным зачёркнутым (C00000), новое — фиолетовым (7030A0).
- Раскрывающийся блок: абзац `▼ Раскрывающийся блок «Заголовок»` в начале, абзац `▲ Конец раскрывающегося блока` в конце.
- Отчёт в чате короткий: что сделано, что нужно решить автору; подробности — в `proverka-*.md`.

`tools/redline/` — сборка редлайна из файла автора (описание в `tools/redline/README.md`).
